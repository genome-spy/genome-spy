Why these API additions are needed

Core loads the JSON file, filters categories using categoryCount, and calculates each interval's length. The existing parameter API changes that filter. view.readData({limit: 100}) returns the resulting records, including the derived length.

The existing loading API tells the page when a URL-backed filter has finished publishing new records before it reads again.

The page does not fetch a second copy of the input or repeat those transforms. The old parameter API could change the filter, but could not read its output. This is the gap readback fills.

Zooming does not filter readback: it returns the whole loaded transformed collection. Rows removed by transforms are absent. For raw input, an app retains or retrieves its own source data. Readback does not load missing data or guarantee that every returned row produces visible pixels.
