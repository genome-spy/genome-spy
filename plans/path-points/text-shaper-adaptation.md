# Focused `text-shaper` adaptation record

Status: implemented; provenance maintained in the vendor directory

## Decision

GenomeSpy does not use `text-shaper` as an MSDF generator. Its focused
rasterizer omitted correctness-critical behavior and produced acute-corner
seams. Canonical msdfgen became the development oracle and the production atlas
is generated by GenomeSpy's WebGPU implementation.

Only the small dependency-free static TrueType reader was adapted. It lives
under the required provenance boundary:

```text
packages/webgpu-renderer/src/vendor/textShaper/
    LICENSE
    NOTICE.md
    README.md
    font/
        reader.js
        trueType.js
        positioning.js
```

The authoritative upstream revision, source-file mapping, modifications, and
license are recorded in `NOTICE.md`; capability boundaries are recorded in the
adjacent vendor `README.md`. Those files, rather than this temporary plan, must
remain with the shipped source.

## Implemented subset

- SFNT table directory and bounded binary reader.
- Unicode `cmap` formats 4 and 12.
- `head`, `maxp`, `hhea`, `hmtx`, `loca`, and quadratic `glyf` data.
- Simple and composite TrueType outlines with recursion validation.
- Horizontal advances and font metrics.
- Basic `latn`/`DFLT` GPOS `kern` selection.
- Pair Adjustment lookup type 2, formats 1 and 2.
- Type 9 extension wrappers targeting pair adjustment.
- Legacy horizontal `kern` format 0 fallback.

Renderer-owned adapters outside the vendor subtree handle glyph/path
conversion, layout, font-resource APIs, atlas requests, caching, WebGPU state,
and Core integration.

## Explicitly unsupported

- GSUB and complex-script shaping.
- Bidirectional ordering and Unicode line breaking.
- Multi-font fallback runs.
- Variable fonts and device/variation positioning.
- CFF/CFF2, WOFF/WOFF2, color glyphs, hinting, and bitmap strikes.
- Vertical positioning, mark filtering, and alternate language systems beyond
  the focused basic-kerning selection.

Unsupported formats fail explicitly where the reader can identify them. Full
shaping should be delegated to a dedicated library if future requirements
justify its bundle and maintenance cost; it should not emerge through gradual,
unbounded additions to this focused parser.

## Ongoing constraints

- Keep all copied or materially adapted upstream code and notices inside the
  vendor directory.
- Renderer modules import a narrow GenomeSpy-owned adapter, not scattered
  vendor internals.
- Point-only entries must not include font parsing code.
- Do not reintroduce the rejected `text-shaper` rasterizer.
- Add parser fixtures and provenance updates whenever the supported table
  subset changes.
